# Adversarial review — 2026-09-16

Independent review of git `94fd2fb`, four weeks after the build. Nothing in the existing docs was
taken on trust; every claim below was checked against the code, and every **confirmed** finding has
a reproduction in `ext/src/review-2026-09-16.test.js` that runs the real shipped source in a
`node:vm` realm. Test names are quoted so a finding can be re-run in isolation:

    cd ext && node --test --test-name-pattern="A1a" src/review-2026-09-16.test.js

⚠ Those tests **pass while the defect is present**. They assert what a hostile page can do today.
When a finding is fixed the matching test goes red — flip it into a regression guard then, don't
"fix" the test. A green run of that file is the review still being true.

Rules I held to: reproduce before reporting (confirmed vs. suspected are separate sections); rank
by impact — **(a)** a page can strip protection, **(b)** a contradiction that identifies Nullecho
users, **(c)** entropy / integrity only; a detectable-but-consistent persona is acceptable, a
self-contradicting one is not (D11). None of `shim.js`, `shim-loader.js`, `gpc.js`,
`personas.js`, `protocol.js`, `persona-validator.js` were edited.

---

## Verdict up front

**Not shippable as-is for Chrome on Mac/Windows.** Not because the design is wrong — the
per-origin persona, the nonce handshake and the read gate are all the right shape — but because
three things the canonical claim rests on are currently false against a page script of under
thirty lines, none of which needs to win the `document_start` race:

1. **The noise is invertible.** Canvas, WebGL and audio noise are deterministic *and
   content-independent*, so a page learns the exact perturbation from a known input (a uniform
   grey fill; a silent buffer) and subtracts it from the real fingerprint. The recovered bytes
   are identical across sites. The cross-site join — the one thing THREAT-MODEL.md says Nullecho
   breaks — is restored. (A1)
2. **The handshake's "only way in is to beat the race" claim is false.** Section 0a captures four
   primitives; the code then calls a dozen others at run time through the page's own prototypes.
   Hooking `String.prototype.charCodeAt` makes a forged nonce match and stands the shim down.
   Hooking `Function.prototype.call`/`apply` hands the page the *native* getters the shim
   delegates to for its brand check, i.e. the real machine on every spoofed property. (A2)
3. **eTLD+1 is wrong in both directions.** The service worker keys every `*.myshopify.com` and
   `*.wordpress.com` tenant as one site — one persona for all of them, and allowlisting one store
   writes a DNR `allowAllRequests` rule that switches Nullecho off on every Shopify store. The
   shim's own (different) table lacks `co.il`, `co.id`, `com.ua`, `com.pl`, … so Israeli,
   Indonesian, Ukrainian and Polish users get one fallback persona across their national TLD. (A4)

Plus two (b)-class contradictions that affect large populations *today*: every non-`en-US` user
(`navigator.language` pinned to `en-US` while `Intl` and `Accept-Language` stay real — B1), and
every user whose Chrome is not exactly 151 (the persona pins Chrome/151 in JS while the browser
sends the real version in `User-Agent` and `Sec-CH-UA` on every request — B2). B2 is a ticking
clock: it is true for nobody today and for everybody after the next Chrome update.

Everything in A1–A4 is fixable inside the current architecture; rough costs are given per item.
What I would *not* do is ship before A1, A2, A3, A4 and B1/B2 are closed, because each one is
cheaper to exploit than the defence it defeats, and the audience most likely to evaluate this tool
(the docs say so themselves) is the audience most likely to try exactly these.

## Confirmed — (a) a page can strip protection

### A1 — Deterministic, content-independent noise is invertible; the join is restored
`A1a`, `A1b`, `A1c` · shim.js `noiseRGBA`, `noiseFloat`, `readPixels`

The noise for a pixel depends only on `(persona key, canvas w×h, absolute coordinate)` — never on
the pixel's value. So a page does this:

```js
// 1. learn the pattern for this canvas size from a known input
const p = mk(64, 32); p.fillStyle = 'rgb(128,128,128)'; p.fillRect(0, 0, 64, 32);
const pattern = Array.from(p.getImageData(0, 0, 64, 32).data, (v, i) => i % 4 === 3 ? 0 : v - 128);
// 2. subtract it from the real fingerprint canvas of the same size
const real = Array.from(fp.getImageData(0, 0, 64, 32).data, (v, i) => v - pattern[i]);
```

`A1a` shows the recovered bytes equal the true buffer exactly. `A1b` boots two realms on two
sites with two different personas (different noise keys, different noised output) and shows the
*recovered* bytes are byte-identical — a cross-site canvas join. Audio is worse: `A1c` shows a
never-written `AudioBuffer` reads back as the noise vector itself (all zeros in every real
browser — also a detector, see B4), and subtracting it recovers the real samples to float32
rounding (max error < 1e-7 against ±1e-7…8e-7 noise). Audio fingerprints hash rounded sums; that
error is invisible to them.

The docs already publish the uniform-fill *detector* (`{126,127,128,129,130}`) and call it
"what canvas noise is". It is also the first half of this attack. Boundary pixels (values within
2·mag of 0/255 in the perturbation direction) are ambiguous after subtraction; an attacker masks
them or quantises, and the rest is exact.

**Fix (design, ~day):** key the noise on a digest of the *content* as well as the persona key,
e.g. `key = mix(canvasKey, w, h, fnv(pixels))`, so a known input teaches nothing about any other
image. Then the sub-rect/full-read agreement the kernel comment promises needs to be re-derived
(it is already broken — B5): compute the digest over the whole canvas once per read and slice.
Audio: same, digest the samples; and never noise an all-zero buffer (the canvas kernel already
has the "blank canvas realism" rule — audio has no equivalent). Re-measure the averaging attack
after: content-keyed noise stays deterministic per content, so 50 reads still give one hash.

### A2 — Uncaptured builtins: forged stand-down, native leak, noise bypass
`A2a`–`A2f` · shim.js §0a and everywhere `.call` / `.apply` / `charCodeAt` / `Math.imul` /
`.length` are used at run time; gpc.js `nonceMatches`

Section 0a's premise is that a page which runs *after* the shim can't influence the handshake.
That holds only for the four primitives captured there. Each of these runs in normal page timing
(after `document_start`, before the service-worker reply lands or at any later moment):

| Hook | Effect | Test |
|---|---|---|
| `String.prototype.charCodeAt = () => 0` | `nonceMatches()` compares 32 zeros to 32 zeros → any 32-char nonce matches → `{enabled:false}` is obeyed → **`restoreAll()`, real machine** — and the shim reports `allowlisted` to the popup | `A2c` |
| same, against gpc.js | `applyConfig({gpc:false, gpcNonce:'0'.repeat(32)})` accepted → `navigator.globalPrivacyControl` deleted | `A2d` |
| `Function.prototype.call` hook | every `spoofGetter` does `origGet.call(this)` for the brand check — the hook receives the **native getter as `this`**; `Reflect.apply(native, navigator, [])` → real `userAgent`, `platform`, `hardwareConcurrency`, `deviceMemory`, `languages`, `userAgentData.*` | `A2a` |
| `Function.prototype.apply` hook | `replaceMethod` wrappers do `orig.apply(...)` — leaks native `getParameter` (real GPU renderer) and native `toDataURL`/`getImageData` (un-noised canvas) | `A2b` |
| `%TypedArray%.prototype.length` getter → 0 during one read | `noiseRGBA`'s ink scan sees length 0 → `hasInk=false` → returns without noising → **real pixels**; same gate in `readPixels` | `A2e` |
| `Math.imul = () => 0` | `prf`, `fin32`, `keyMix` all collapse to 0 → noise becomes a fixed −1 on every channel, **independent of the persona key** → identical bytes on every site | `A2f` |

`A2a`/`A2b` matter beyond the handshake: the brand-check delegation ("always invoke the original
first", ARKENFOX-RESPONSE (f)) is what hands the natives over. Also unguarded, same class:
`WeakMap.prototype.get` in the patched `toString` (C2), `Array.prototype.filter/map` on the real
WebGL extension list, `Set.prototype.has`, `Object.freeze`, `Promise.resolve`, `Math.max/min`.

**Fix (mechanical, ~half day + a regression test that hooks all of them):** capture
`Reflect.apply` at boot and replace every `fn.call(t, …)` / `fn.apply(t, a)` with
`apply(fn, t, a)`; capture `Math.imul`, `Math.floor`; compare nonces through a captured
`charCodeAt` (`apply(charCodeAt, expected, [i])`) or compare byte arrays produced at mint time;
compute buffer lengths from `w*h*4`, never from `.length`; wrap the WeakMap in captured
`get`/`has`. The existing tests hook `CustomEvent.prototype.detail` and `JSON.parse` only —
extend that test to a table of every builtin the shim touches after boot, and make it fail on
any new bare method call (a lint-style grep for `\.call\(|\.apply\(` in shim.js/gpc.js would
catch regressions).

### A3 — The persona payload, noise keys included, is delivered to the page
`A3` · shim.js §9(a) `onPersonaEvent`, gpc.js `onPersona`

The shim's window-capture listener consumes the handshake first — correct — but never calls
`stopImmediatePropagation()`, so a page listener registered on `window` (capture) reads the same
event: `persona.noise.{canvas,audio,webgl}`, `persona.seed`, the nonce. `shim-handshake.test.js`
already observes the nonce leaking and calls it harmless because the nonce is spent. The noise keys
are not spent: with the key and the (public) kernel a page computes the exact perturbation for any
canvas size without even drawing a probe. This must be fixed *alongside* A1 — content-keyed noise
plus a leaked key is still computable.

**Fix (2 lines, one trap):** call a captured `Event.prototype.stopImmediatePropagation` in the
shim's listener after `detailOf()`. Trap: gpc.js listens on the same event and registers *after*
the shim, so it would never hear its config. Either the loader dispatches two events
(`nullecho:persona` for the shim, a new one for gpc, each consumer stopping propagation), or the
shim re-dispatches a stripped payload for gpc. Also stop sending `seed` — nothing in the shim
uses it except `fontKey`, which can be derived in the worker.

### A4 — eTLD+1 confusion in both layers, and the two tables disagree
`A4a`–`A4d` · heuristics.js `MULTI_LABEL_SUFFIXES` (used by `background.js siteKeyFor`);
shim.js `MULTI_LABEL_SUFFIXES` + `registrableDomain`

- **Service worker** (`A4a`, `A4b`): `siteKeyFor('https://acme-store.myshopify.com')` →
  `'myshopify.com'`. Every Shopify store gets the same salted persona (zero cross-site
  separation across ~5M storefronts), and `SET_SITE_ENABLED` for one store adds `'myshopify.com'`
  to the allowlist → dynamic rule `{allowAllRequests, requestDomains:['myshopify.com']}`, which
  DNR matches on every subdomain → blocking off and the shim standing down on **every** store.
  `A4b` drives the real message handler and reads the rule back. Same for `wordpress.com`
  (`alice.wordpress.com` ≡ `bob.wordpress.com`) and `tumblr.com`. The shim's table has all three;
  the worker's does not.
- **Shim fallback** (`A4c`): the shim's table lacks `co.il`, `co.id`, `co.th`, `com.ua`,
  `com.pl`, `com.ru`, `com.es`, `com.ph`, `com.vn`, `com.sa`, `com.eg`, `com.pk`, … (the worker's
  has them). `ynet.co.il` and `walla.co.il` derive the same fallback persona from key `'co.il'`.
  The fallback is what every page that reads a shimmed API before the worker replies is locked
  to (R1) — which on real pages with head-of-document analytics snippets is most of them.
- `A4d`: the tables differ on **41** entries and nothing pins them together. The shim's comment
  says it "mirrors `siteKeyFor()`"; it does not.

**Fix (~half day):** one generated table shared by both files (the protocol.js drift test is the
template), or ship the ICANN+private PSL sections (~60 KB gzipped) and stop hand-listing. At
minimum add the missing private suffixes to the worker's list and pin the two with a test.

### A5 — Three attacker-controlled pages can get any third-party domain blocked for the user
`A5` · heuristics.js `onBeforeRequest` → `hasIdentifierParam` → `recordSignal` → `applyAction`

The `ID_PARAM` strike is derived entirely from the *request URL*, which the embedding page
controls. Three first parties on separate registrable domains (three free GitHub Pages sites
qualify — `*.github.io` is, correctly, three different eTLD+1s) each embedding
`<img src="https://cdn.victim.example/x.png?gclid=Q7Q7Q7Q7Q7Q7Q7Q7Q7Q7Q7Q7Q7Q7">` promote
`victim.example` to a dynamic `block` rule for that user, everywhere it appears as a third party.
`A5` feeds the real `webRequest.onBeforeRequest` listener and reads the rule back. Only
`NEVER_BLOCK` and the eleven `ENTITY_GROUPS` are immune. A bank's API host, a competitor's CDN or
a payment-page asset host is not. The rule persists across restarts (`reconcile()` re-adds it).

**Fix (design):** don't promote on `ID_PARAM` alone — require a second signal class (a
high-entropy cookie *set by the tracker*, which the attacker cannot forge), or treat
single-signal promotions as `cookieblocked` rather than `block`. Discount strikes whose first
party is itself on a free-hosting suffix.

### A8 — Workers (documented gap G1, re-rated)
Not reproducible here; the code and manifest simply have no worker path. Recording it under (a)
because the docs file it under "known gaps" without saying what it costs: four lines —
`new Worker(URL.createObjectURL(new Blob(['postMessage([navigator.userAgent,navigator.hardwareConcurrency,navigator.deviceMemory,navigator.platform])'])))`
— return the real machine, and an `OffscreenCanvas` in that worker returns the real canvas hash.
That both restores the join and contradicts the main-thread persona (b). CreepJS and
FingerprintJS Pro both run worker-scope checks specifically to catch spoofing extensions. A
partial mitigation exists (wrap the `Worker`/`SharedWorker` constructors: fetch same-origin/blob
classic-worker sources and prepend the shim; module workers and cross-origin scripts stay
uncovered) — it is a design decision, not free, and detectable via `self.location` — but "none
available" in THREAT-MODEL.md overstates it.

## Confirmed — (b) contradictions that identify Nullecho users

### B1 — `navigator.language` pinned to `en-US`; `Intl`, `toLocaleString`, `Accept-Language` real
`B1` (child process under `LANG=de_DE.UTF-8`)

Shim: `navigator.language === 'en-US'`, `languages` `['en-US','en']`. Same realm:
`Intl.DateTimeFormat().resolvedOptions().locale === 'de-DE'`, `(1234.5).toLocaleString() ===
'1.234,5'`, `toLocaleDateString() === '16.9.2026'`. In a clean Chrome these are one preference;
they never disagree. The `Accept-Language` request header is real too (no DNR rule touches it),
so a server sees `de-DE` while the page's JS says `en-US`. Every non-`en-US` user is flagged; the
pinning buys nothing (the personas carry no locale, and the docs' own reason for leaving timezone
real applies verbatim here). **Fix:** stop spoofing `language`/`languages` (D11: a consistent
leak beats an inconsistent fake), or spoof `Intl` too and rewrite `Accept-Language` via DNR — the
first is one deletion, the second is a project.

### B2 — Chrome version pinned to 151 in JS; real version in `User-Agent` / `Sec-CH-UA` headers
`B2`

Every persona says `Chrome/151.0.0.0` and brands `v="151"`; the host in the test says 152, the
shim still reports 151. Nothing in `rules/*.json` or `src/*.js` touches `User-Agent`,
`Sec-CH-UA`, `Sec-CH-UA-Full-Version-List`, `Sec-CH-UA-Platform-Version` or `Sec-CH-UA-Arch`
(static grep in the test). Chrome sends the low-entropy hints on *every* request and the
high-entropy ones to any site that sends `Accept-CH` — which the big fingerprinting vendors do.
Server-echo-vs-client comparison is a standard spoof check. After the next Chrome update this
contradicts for 100% of users; it also already contradicts on `Sec-CH-UA-Platform-Version`
(persona `14.6.0` on macOS 26 hosts) and on `Sec-CH-UA-Arch` for `macos-chrome-intel-iris`
(`x86`) on Apple-silicon hosts. **Fix:** read the real Chrome major from the unpatched UA at boot
(the `HOST_FAMILY` pattern) and substitute it into the persona UA/brands/fullVersionList; drop or
host-gate the Intel-Mac persona; consider whether `platformVersion` should also track the host.

### B3 — Same-origin `about:blank`/`srcdoc` children present a *different* machine than the parent
`B3a`, `B3b`

The shim keys its fallback on `registrableDomain(location.hostname) || location.origin`. In a
blank child `hostname` is `''`, so the key is the origin **URL string** (`'https://www.news.example'`),
not the eTLD+1 (`'news.example'`) — a different seed, hence (for ~80% of sites) a different
persona. And the worker refuses to upgrade it: `siteKeyFor('about:blank') === ''` →
`{ok:false, error:'unsupported scheme'}` (`B3b` drives the real handler with
`sender.url='about:blank'`), so the child is locked to that fallback while the parent runs the
salted persona. `iframe.contentWindow.navigator.hardwareConcurrency !== window.navigator.hardwareConcurrency`
is the "pristine child realm" detector the docs call *clean* for the `.contentWindow` path.
Caveat: in a browser the parent's `installInto(childWindow)` wraps the child's descriptors
*again*; whichever wrapper is outermost wins, and that depends on whether Chrome injects the
child's own content script before or after the parent first touches `contentWindow`. The
`window[0]` path never runs `installInto`, so there the child's own persona is what is read.
**Fix:** key on `registrableDomain(new URL(location.origin).hostname)`; in the worker, fall back to
`sender.origin` when `sender.url` is `about:`/`blob:`/`data:`.

### B4 — Silence is noised (audio)
`A1c`, `B4`

A fresh `AudioBuffer` reads back non-zero; `getByteFrequencyData` on a silent analyser returns
bins of 1. No real browser does either. Two-line detector, and the audio half of A1. **Fix:** the
canvas kernel's "no ink → no noise" rule, applied to audio.

### B5 — Sub-rectangle read vs. full read of the same region disagree
`B5`

`noiseRGBA`'s `hasInk` gate is evaluated on the *returned rect*. A transparent corner read alone
is untouched; the same corner inside a full-canvas read is noised (the kernel deliberately noises
whole regions once any ink is present). The kernel's docstring promises the opposite ("the two
read paths cannot be differenced"). Detector; and contradicts the code's own claim. Folds into the
A1 redesign.

### B6 — WebGPU `architecture` is one constant per vendor
`B6`

`webgpuIdentity()` maps every Intel renderer to `gen-9` and every NVIDIA to `ampere`. The pool
contains `win11-chrome-iris-xe` and `linux-chrome-mesa-xe` (Tiger Lake — Gen12; Dawn's GPU table
reports it as `gen-12lp`) and `win11-chrome-rtx4060` (Ada Lovelace, not Ampere). The WebGL
renderer string and the WebGPU adapter info of one persona therefore name two different GPU
generations. The code already flags the table as unverified; this is the concrete contradiction.
**Fix:** move the mapping into `personas.js` per persona (the file's own TODO) and verify each
against real Chrome — do not trust my values either.

### B7 — Fresh arrays per read where Chrome returns the same `FrozenArray`
`B7`

`navigator.languages === navigator.languages` and `userAgentData.brands === userAgentData.brands`
are `true` in Chrome (WebIDL FrozenArray attributes are cached) and `false` under the shim (a new
`Object.freeze([...])` / `.map()` per read). One-line detector. **Fix:** cache the frozen arrays
on the derived persona.

### B8 — `maxTouchPoints` pinned to 0; touch-event surface real
`B8`

On a touch-screen Windows laptop `'ontouchstart' in window`, `TouchEvent`, and
`matchMedia('(any-pointer: coarse)')` (untested here) all say "touch", `maxTouchPoints` says 0.
Not a rare configuration. **Fix:** leave it truthful (the personas are all desktop; 0 vs 10 is a
bit, not a persona field).

### B9 — `Object.prototype.dev = true` installs the dev surface on the genuine handshake
`B9`

`if (payload.dev === true) installDevSurface()` reads through the prototype chain. A page that
sets `Object.prototype.dev = true` before the worker replies gets `window.__nullechoDev` —
version string, persona id, `forged`/`reads` counters, `failures` with stack traces (which name
the extension's URL). A certain detector and an internals leak on a production page. **Fix:**
`Object.hasOwn` on every payload field the handshake branches on, or parse into a null-prototype
object.

## Confirmed — (c) integrity / entropy

### C1 — The MAIN→ISOLATED reverse channel is unauthenticated
`C1`

`nullecho:status` and `nullecho:detect` carry no nonce. A page dispatching
`{phase:'boot', channel:'gpc'}` after page scripts have run makes the loader raise the sticky
`nonce-exposed` warning; `{upgraded:true}` overwrites `lastShimStatus` (hiding a real
`lockedToFallback`); `{api:'canvas', count:1e6}` adds a million to the popup's fingerprinting
counter. The popup renders all of it with `textContent` (checked — no HTML injection). Integrity
of what the user is told, not protection. **Fix:** let the loader mint a second nonce, deliver it
in the persona payload, and require it on every later report (the shim holds it in its closure).

### C2 — `WeakMap.prototype.get` hook exposes `NATIVE_SRC` — a certain membership oracle
`C2`

The patched `Function.prototype.toString` does `NATIVE_SRC.get(this)`; a page hook receives the
WeakMap as `this` and can then `has()` any function: `true` for every function the shim replaced,
`false` for everything else. Detection is an accepted cost in the docs, but this is exact and
enumerable rather than probabilistic, and it is the same root cause as A2.

### C3 — The heuristics layer's CANVAS / SUPERCOOKIE signals are dead code
`C3`

`handleContentReport()` waits for `{type:'nullecho:signal', signal, scriptUrl}`. No file sends it;
the loader forwards `nullecho:fp-detected`, which only bumps a counter. The heuristics header,
ARCHITECTURE.md and the strike bitmask all describe a signal path that does not exist. Neither a
bug nor a hole — a docs/code drift that makes the learner weaker than described (and, happily,
means C1's forged detects cannot reach the promotion path).

## Suspected, unconfirmed (code-evident or browser-only; not reproduced here)

- **`readPixels` bypasses.** Only the `RGBA`/8-bit-view path is noised. WebGL2 `readPixels` into a
  `PIXEL_PACK_BUFFER` (arg 6 is an offset, not a view → `ArrayBuffer.isView` fails) followed by
  `getBufferSubData`, or a `FLOAT` read from a float FBO, returns un-noised rasteriser output.
  Every persona claims WebGL2. Code-evident; needs a browser to demonstrate.
- **`performance.memory.jsHeapSizeLimit` vs `deviceMemory`.** V8 sizes the heap limit from
  physical RAM (≈2 GB class on 8 GB hosts, 4 GB class on 16 GB+). A persona claiming `memory: 8`
  on a 32 GB host will show a 16 GB+ heap limit. Probe:
  `[navigator.deviceMemory, performance.memory.jsHeapSizeLimit]` on each persona in
  `harness/shim-test.html`.
- **CSS `(any-pointer: coarse)` / `(hover: none)`** vs `maxTouchPoints: 0` (B8's style-engine
  half). Same mechanism as the display-layer retreat in D11.
- **`Sec-CH-UA-*` / `Accept-Language` headers** — asserted by construction in B1/B2 (nothing
  rewrites them); the actual header bytes were not captured in a browser here.
- **Child-frame wrapper ordering** for B3 via `.contentWindow` (see caveat there).
- **`Function.prototype.toString` on the WebGPU `Symbol.iterator` wrapper** — `markNative` names
  it `'[Symbol.iterator]'`, so `toString` reports `function [Symbol.iterator]() { [native code] }`;
  real Chrome reports `function values() { [native code] }` for `GPUSupportedFeatures`. Untested.
- **MV3 / platform drift:** nothing found that a four-week-old build would have missed. Notes
  for the record — `world:"MAIN"` static declaration is still the earliest hook and the
  injection race is still Chrome's; `chrome.storage.session` is (correctly) unused; extension-page
  CSP is fine; DNR `requestDomains` matching subdomains is what makes A4b bite; `sender.url` is
  `about:blank` (not the inherited origin) for blank frames, which is B3b. Firefox `world:"MAIN"`
  and `match_about_blank` are current. `minimum_chrome_version: 121` is comfortably below
  everything used.

## What holds up

Worth saying, because a review that only lists defects misrepresents the code:

- The nonce handshake's *event-ordering* argument is right. Window-capture first, registered at
  `document_start`, is genuinely ahead of any page listener; rejection not consuming the one-shot
  is the correct call; the loader's ISOLATED-world race measurement is the honest version of that
  check. The forgeries in `shim-handshake.test.js` all still fail. A2 goes around the nonce, not
  through it.
- Salt containment is real: the salt never leaves the worker, `sender.url` is the only origin
  source, and the persona for one origin gives away nothing about another (`seed` is a 32-bit FNV
  of a 128-bit secret).
- The read gate, the fallback-first patching order, the D12 host-family constraint and the
  descriptor-preserving patches are all sound and all tested. The Illegal-invocation brand check
  is right in intent — it just needs to be done through a captured `Reflect.apply`.
- No page-reachable path into the worker's message surface; `externally_connectable` is absent;
  the popup/options render with `textContent` throughout.
- The heuristics layer can never promote a `NEVER_BLOCK` entry (verified by its own tests); A5 is
  about what it *can* promote, not about that guard.

## Suggested order of work

1. **A2 + C2** (uncurry every builtin call; one regression test hooking all of them) — half a day,
   no design decisions, closes the forged stand-down and the native leak.
2. **A3** (stop propagation; split the gpc event) — an hour, one trap.
3. **A1 + B4 + B5** (content-keyed noise; no-noise-on-silence) — a day including re-measuring
   determinism and the averaging attack in `harness/shim-test.html`.
4. **A4** (one shared suffix table, pinned; or ship the PSL) — half a day.
5. **B1, B2, B7, B8, B9** — each under an hour; B2 needs the "track the real Chrome major"
   decision recorded in DECISIONS.md.
6. **A5** and **B3** — design calls; write the decision first.
7. **B6** — verify against real hardware before touching the table.
