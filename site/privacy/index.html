Nullecho

Privacy policy

This covers two separate things with two separate answers: the browser extension, which collects nothing and has nowhere to send anything; and this website, which is hosted by someone else who keeps server logs. Saying only the first half would be the kind of claim this project exists not to make.

Effective 2026-10-14 (Nullecho 0.9.2). It covers the extension in Chrome, Microsoft Edge and Firefox — the same code runs in all three. Every claim about the extension was checked against the source in ext/, not asserted from memory — the grep citations are below.

What Nullecho does

Nullecho blocks trackers (ads, analytics, social pixels, known fingerprinting vendors), sends the Global Privacy Control signal, shows each site a different but internally-consistent device profile, points out when a shopping page has displayed one of the algorithmic-pricing sentences a U.S. state mandates, and offers a guided link to California's data-broker deletion platform (DROP).

Two qualifications belong here rather than in a footnote.

The device profile breaks most fingerprint joins, not all of them

It breaks the join for trackers that hash the signals Nullecho covers — verified 2026-09-17 against FingerprintJS 5.2.0 and ClientJS, which gave four personas four distinct visitor IDs. It does not break it for a lie-aware library: CreepJS discards values it catches being spoofed, keys on what is left, and re-joins the personas into one identity. Nullecho is detectable by design and does nothing about your IP address.

Global Privacy Control depends on where you live

It is a legal do-not-sell request if you live in a state that recognises it — California, Colorado and several others. The duty attaches to your residency, not to where the site is, and whether a given business is covered, or acted on the signal, happens on their servers where a browser cannot see it. The signal covers this browser profile only: your phone and your other browsers each need their own.

Data collected: none

Nullecho has no server, no account, no sign-in, no telemetry, no analytics, and no crash reporting — it does not send a single byte about you or your browsing to anyone, ever.

How we know this, not just claim it: grepping the shipped extension source (ext/src/, ext/popup/, ext/options/) for every way a web page or extension can reach the network finds exactly two fetch() calls in the whole codebase: 

ext/src/background.js   fetch(chrome.runtime.getURL(`rules/${id}.json`))
ext/src/gpc.js          fetch(chrome.runtime.getURL(RULESET_PATH))

Cited by file and expression rather than by line number, deliberately — a line number in a published policy rots silently. At commit 33dfefa they are background.js:97 and gpc.js:349; the automated test below is what actually holds the claim.

Both read a JSON file bundled inside the extension package — chrome.runtime.getURL(...) resolves to chrome-extension://… (in Firefox, moz-extension://…), never a remote host. There is no other fetch, XMLHttpRequest, navigator.sendBeacon, WebSocket, EventSource, or importScripts anywhere in the shipped source — enforced by an automated test (ext/src/manifest.test.js) that fails the build if any of those appear, or if a fetch() argument is not a bundled-file chrome.runtime.getURL(...).

"Analytics" and "telemetry" do appear in the source — as the category label for third-party trackers Nullecho blocks (Google Analytics, Mixpanel, and so on) and in a lookup table (ext/src/linkage.js) naming which company a blocked domain belongs to, shown only to you, locally. None of that data leaves your device.

Data stored locally

Nullecho keeps what it stores in three places, all inside your browser profile on your own machine, and Chrome, Microsoft Edge and Firefox delete all three automatically when you uninstall the extension. Nothing is synced to your Google, Microsoft or Mozilla account: storage.sync is never used, and the same build-failing test fails the build if storage.sync appears in any shipped file.

1. chrome.storage.local (in Firefox, the same store under browser.storage.local). Grepping every storage.local.set call in the source gives this exact list:

KeyWhat it holds
identityA random salt — it decides which device profile each site sees — and when it was last rotated. The salt itself is never shown or sent anywhere; the popup and settings page show only a six-character tag derived from it.
settingsWhich tracker categories you block, whether GPC is on, whether you said you live in California (it only decides whether the DROP step is suggested), the salt auto-rotation interval, and loud-failure logging.
allowlistSites where you've turned Nullecho off.
statsOne entry per site whose pages — or frames embedded in a page — you load, by site name (for example example.com), never a page address: when it was last seen, how many fingerprinting reads were seen and of which kind, which device profile the site was shown, whether the page-world script started properly, and how many requests were blocked and to which tracker domains (in a store install, taken from the browser's own report that an extension cancelled a request, and counted only when one of Nullecho's own rules covers it). Requests that went through with their cookies removed are counted only in unpacked developer builds of Chrome and Edge, the one place the browser reports them. At most 500 sites (when the list is full, the least recently visited tenth is dropped) and 60 tracker domains per site.
nullecho:heuristics:v1The tracker learner. For each third-party domain seen setting or sending an identifying cookie: the names of the sites it was seen on, whether it has been learned as a tracker (three different sites), and when it was first and last seen. It keeps domain names, never a cookie's value.
nullecho:gpc:v1Sites where you've manually excepted the GPC signal because it broke something.
nullecho.drop.residency
nullecho.drop.submittedAt		Your California-residency answer and a date you typed, only if you use the DROP guide. Deliberately excludes name, birthdate, ZIP, and the state's deletion-request ID — those live only on California's own site, which Nullecho links to.

For each: the site, the page address with its query string removed, the time, which state's wording it was, the price and currency the page published, and up to 200 characters of the page's own text around the sentence. At most 200 entries. Details below.

What that adds up to, plainly. stats and the tracker learner are, between them, a list of the sites you have loaded — by site name, with when each was last seen — and pricingObservations holds a page address and a short excerpt of page text for each of the (rare) pages it describes. All of it stays in this browser profile on this machine.

The price-disclosure observations

What is stored, and when. Nothing, on almost every page. A page is recorded only if it shows one of the two sentences — New York's "this price was set by an algorithm using your personal data" or Connecticut's "this price was increased using your personal data" — and also publishes a price in structured product data. The check runs on the top-level page in Chrome, Edge and Firefox alike, once when the page has loaded and once about three seconds later.

How long it is kept. There is no time limit. An entry stays until there are more than 200, when the oldest is dropped, or until you uninstall the extension. Seeing the same page, wording and price again replaces the earlier entry instead of adding one. The settings page's "Clear saved price notices" button deletes them all, and shows how many there were and how many are left; uninstalling removes them too.

Whether it leaves your device. It does not. No code in the shipped extension can send it anywhere — the build-failing test above covers it like everything else. The popup shows the latest entry for the site you are on, and its "Copy receipt" button puts that entry's text on your clipboard when you click it; where it goes from there is up to you.

2. The browser's own rule list (declarativeNetRequest dynamic rules). Blocking and header changes are rules the browser itself applies, and three kinds of rule that Nullecho adds hold domain names: the sites you turned Nullecho off on, the sites you turned GPC off on, and the tracker domains the learner promoted.

3. storage.session — memory only, never written to disk and never synced. One key, nullecho:tab-blocked: for each open tab, how many requests Nullecho blocked on the page in it, by category — numbers, no addresses. It is how the popup's "blocked on this page" survives the background script being put to sleep. A tab's entry is dropped when it loads a new page or closes, and all of it when the browser closes.

One honest footnote, because this list is presented as a grep result and a grep for localStorage finds something: ext/options/drop.js:83-105 falls back to localStorage when the DROP page is opened outside the extension — local development only. In a packed install chrome.storage.local always exists, so that path never runs.

Data shared: none

Nullecho has no backend to share data with. The permissions it requests let it watch and modify requests inside your own browser — none of them involve sending anything to Nullecho or to any third party.

Permissions, and why each is needed

  • declarativeNetRequest / declarativeNetRequestFeedback — the rules that block trackers, add the GPC header, strip cookies from some requests and remove some client-hint headers. The browser applies them itself. In Chrome and Edge the popup's per-tab count asks the browser which rules acted in the current tab; in a store-installed build the browser answers with rule numbers, not request addresses. Firefox offers no such report; there the count comes from the webRequest report described next.
  • storage — the local-only data above. alarms — wakes the background script to rotate your salt if you've turned that optional feature on.
  • webRequest (observation only, not webRequestBlocking) — lets the tracker learner look at the requests your pages make: each request's address, the page that made it, the Cookie header sent and any Set-Cookie header returned. It ignores page loads themselves and first-party requests, it can't block anything itself, it keeps only what the learner's row above describes, and nothing it sees is ever transmitted anywhere. The same permission delivers the browser's report that an extension cancelled a request — Nullecho counts it as blocked only when one of its own rules covers it, keeping the site name and tracker domain shown in stats — and the start of each new page in a tab, which resets that tab's count.
  • host_permissions: ["<all_urls>"] — needed on every site so blocking, the GPC signal, the device-profile script and the price-disclosure check all work everywhere, not just a list you'd have to remember to maintain.

How to delete everything

  • Uninstall the extension. Chrome, Microsoft Edge and Firefox all delete an extension's storage.local data and the rules it added automatically on uninstall — there is nothing left behind, because there was never anywhere else for it to go.
  • Clear the site list without uninstalling. "Clear site history" on the settings page empties stats. It does not touch the tracker learner or the price-disclosure observations.
  • Clear the price-disclosure observations. "Clear saved price notices" on the settings page deletes every entry in pricingObservations.
  • Get a "new identity" without uninstalling. The popup's "New identity" button generates a fresh random salt and writes it over the old one. Every site then sees a brand-new, unrelated device persona going forward. This does not touch your blocking stats or allowlist — those are separate keys — but it breaks the link between your past and future persona at every site.

The Safari app (iPhone, iPad and Mac)

Nullecho for Safari is the same tracker-blocking and Global Privacy Control, packaged the way Apple requires: a Safari web extension inside a small app from the App Store. It is a smaller extension than the Chrome, Edge and Firefox one — no device profile, no tracker learner, no price-disclosure check — and it collects nothing. Every sentence here was checked against the source in safari/, cited by file and expression like the rest of this page.

What it stores: nothing

The Safari extension (safari/extension/manifest.json, assembled by safari/tools/build-extension.mjs) has no background script and asks for no storage permission — only declarativeNetRequest, declarativeNetRequestWithHostAccess and access to websites. Its two content scripts set the navigator.globalPrivacyControl property on the pages you allow; the Safari-only one (safari/extension/src/gpc-loader.js) makes no request and touches no storage. The shared one is the same ext/src/gpc.js file described above: its half that reads a bundled rule file and chrome.storage.local runs only inside an extension's background worker (IN_EXTENSION_WORKER → otherwise runInPage() and return), and the Safari build has no such worker. The popup (safari/extension/popup/popup.html) is a static page with no script at all.

What Safari itself keeps — that you enabled the extension, and which websites you allowed it on — lives in Safari's own settings on your device, like it does for any extension. Nullecho never reads it.

The app around the extension

The app (safari/xcode/App/) exists because Safari extensions ship inside one. It shows what the extension does, how to turn it on, and — on a Mac — whether it is on. It opens no network connections of its own: on macOS it is sandboxed without the outgoing-network entitlement (ENABLE_OUTGOING_NETWORK_CONNECTIONS = NO in safari/xcode/Nullecho.xcodeproj), and on every platform it contains no URLSession, no web view and no third-party code (the project has no package dependencies) — an automated check (safari/tools/check-container.mjs) fails the build if a URLSession, a web view, a remote address, or any UserDefaults, file or keychain write appears in the app's source. The two links it offers (this policy and the source code) are handed to your browser. The version number and the rule counts it displays are read from the extension bundled inside it (safari/xcode/App/EmbeddedExtension.swift), not typed in.

The tip jar

The app offers four optional tips through Apple's in-app purchase system (StoreKit, safari/xcode/App/TipJar.swift). A tip changes nothing: no feature is locked behind one, and the only thing that happens afterwards is a one-line thank-you that disappears when the app quits. Apple handles the payment under Apple's own terms and privacy policy; the app reads the completed transaction on your device to show the thank-you and mark it finished, stores no record of it (no identifier, no appAccountToken, nothing on disk), and sends nothing to us. We receive no personal information from a tip.

Data collected: none

That is the App Store privacy label the app carries — "Data Not Collected" — and it is literally true: there is no server, account, sign-in, telemetry, analytics or crash reporting in the Safari app or its extension. The one thing it does on the network is what Safari does for it: apply the blocking rules and the GPC header to the requests your pages make, inside your browser.

Two Safari limits, stated plainly

  • Tracker blocking works on every site as soon as the extension is on, before you grant it any website access. Global Privacy Control needs that access, so it applies only on the sites you allow — and Safari attaches the Sec-GPC header to image and script requests only, never to the page itself (safari/CAPABILITY-AUDIT.md). A site's own scripts still see the signal.
  • The Safari version does not change what a site can read about your device. The per-site device profile the Chrome, Edge and Firefox extension offers is not part of it.

How to delete everything

  • Turn it off: on iPhone and iPad, Settings → Apps → Safari → Extensions → Nullecho; on a Mac, Safari → Settings → Extensions.
  • Remove it: delete the Nullecho app. Safari removes the extension with it, and there was never anything else to delete.

The website

The extension collects nothing — there is no endpoint for it to send anything to, which is everything above.

This website is hosted by someone else, and that is not nothing. The pages at nullecho.org/ are served by GitHub Pages. They carry no analytics script, no tracking pixel, no embedded font, no CDN asset, no iframe, and no form — a page load fetches the HTML document and nothing else, which you can confirm in your own browser's network panel right now. But GitHub, as the host, keeps server logs. GitHub's own documentation says so:

"When a GitHub Pages site is visited, the visitor's IP address is logged and stored for security purposes, regardless of whether the visitor has signed into GitHub or not."

GitHub's CDN provider sees the same requests. We neither receive, request, nor have access to those logs, and there is no account through which we could. "The pages collect nothing" is true of the pages; it is not true of the hosting.

Chrome Web Store "Limited Use" disclosure

Google's Limited Use policy governs data obtained through a Google API. Nullecho calls no Google API and requests no Google OAuth scope, so there is no such data to disclose. The Limited Use certification is a required dashboard checkbox set at submission time, not prose written here; the certification made there is the one this document describes — nothing is collected and nothing is transmitted.

Chrome's Handling Requirements ask that user data be transmitted with modern cryptography. Nullecho transmits no user data at all, so the requirement has nothing to attach to.
